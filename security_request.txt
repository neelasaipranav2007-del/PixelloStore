# PHASE 1 — CRITICAL SECURITY IMPLEMENTATION

## 1. Authentication on Every API Route

Secure every protected API route and server action.

- Verify the user's authentication session on the server.
- Reject unauthenticated requests to protected endpoints.
- Validate session expiration.
- Prevent unauthorized access through direct API requests.
- Use centralized authentication helpers where appropriate.
- Ensure sensitive operations cannot bypass authentication.

Do not rely only on frontend authentication or hidden buttons.

## 2. Role-Based Access Control (RBAC)

Implement strict role-based permissions for:

- Admin
- Customer
- Ambassador
- Delivery

Each role must access only its authorized resources.

Examples:

- Customers can access their own orders and profiles.
- Ambassadors can access their own referral and commission information.
- Delivery users can access only their authorized delivery assignments.
- Admin users can access authorized administrative functions.

Enforce roles on the backend, not just in the frontend.

Never trust role information supplied by the browser.

## 3. Row Level Security and Customer Data Ownership

Inspect whether the existing database supports Row Level Security.

If supported and compatible with the current Prisma architecture, implement appropriate database-level policies.

Otherwise, implement equivalent server-side ownership checks on every customer-specific database operation.

Ensure:

- Customers cannot read another customer's orders.
- Customers cannot modify another customer's addresses.
- Customers cannot access another customer's uploaded photographs.
- Ambassadors cannot access other ambassadors' private records.
- Delivery users cannot access unrelated assignments.

Preserve authorized Admin access.

## 4. Never Trust Frontend Data

Treat all frontend-supplied data as untrusted.

Validate the following on the backend:

- Product prices.
- Product quantities.
- Discounts and coupon codes.
- Cart totals.
- Hamper totals.
- Product variants.
- Stock availability.
- Order status.
- Payment status.
- Refund status.
- User roles.
- Delivery status.

Calculate prices and totals using current database records.

Never allow the customer to modify the final payment amount through browser developer tools or API manipulation.

## 5. IDOR Protection

Prevent Insecure Direct Object Reference vulnerabilities.

Check ownership and authorization whenever a user requests a record using an ID.

Protect:

- Customer orders.
- Customer profiles.
- Saved addresses.
- Shopping carts.
- Uploaded photographs.
- Hamper records.
- Ambassador commissions.
- Referral records.
- Delivery assignments.
- Private documents.

Return an appropriate unauthorized or not-found response when access is not permitted.

Do not expose whether another customer's private record exists.

## 6. Razorpay Payment Signature Verification

Secure the complete Razorpay payment flow.

- Create payment orders on the server.
- Verify payment signatures on the server.
- Validate the expected order ID and payment amount.
- Associate payments with the correct PixelloStore order.
- Reject manipulated payment information.
- Never trust frontend payment-success messages.
- Never mark an order as paid without valid verification.

Keep Razorpay secret credentials on the server.

## 7. Razorpay Webhook Signature Verification

Secure all Razorpay webhook endpoints.

- Verify webhook signatures using the configured webhook secret.
- Use the exact raw request body required for signature verification.
- Reject invalid signatures.
- Prevent duplicate webhook processing.
- Store processed event identifiers.
- Make payment and order updates idempotent.
- Validate payment and order associations.

Do not process an unverified webhook as a genuine payment event.

Implement:

- Private storage for customer-uploaded photographs.
- Separate public product catalog images from private customer images.
- Authorized file-access checks.
- Short-lived signed URLs where supported.
- Secure upload and retrieval permissions.
- Safe image deletion and retention procedures.

Do not make private customer photographs publicly accessible through predictable URLs.

## 9. Secure Image and File Upload Validation

Secure all image-upload endpoints, including:

- Product customization.
- AI visual search.
- Hamper customization.

- Image dimensions.

## 10. Admin Portal Route and API Protection

Secure the complete Admin Portal.

- Verify Admin authentication on the server.
- Protect all Admin routes.
- Protect all Admin API endpoints.
- Protect server actions.
